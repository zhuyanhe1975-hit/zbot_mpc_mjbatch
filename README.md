# ZBot MPC with mjbatch

独立验证 ZBot 原地可变周期踏步的状态机与模型预测控制路线。模型资源复制自 `zbot_rl_unilab` 的 MuJoCo 场景；运行时不依赖该强化学习项目。`assets/provenance.json` 保留了模型来源和关节信息。

## 已实现

- 使用 `mjbatch` 对 13 维位置、12 维速度、6 个位置执行器的 ZBot 做并行 MuJoCo rollout；可读取身体与双脚位置、接触传感器，并限制关节位置目标的变化速度。
- 使用 `implicitfast` 积分器稳定运行原始站立位姿。当前场景的执行器参数在 MuJoCo 默认 Euler 积分器下数步内失稳，因此必须在构造 `Batch` 前选定积分器。
- 接触守卫的变频状态机：相邻交替落地的目标间隔为 `T = 1/f`，依次经过重心转移、抬脚、单脚保持、落脚、等待接触；只有目标脚曾离地且双脚重新接触才换侧，原地站着不会被算作一次踏步。改变频率时，在下一次有效换侧后生效。固定阶段时长合计 0.32 秒，剩余时间留给单脚保持，因此 0.5 Hz 保持 1.68 秒，2 Hz 保持 0.18 秒。

**当前没有实现**生成抬脚关节轨迹、重心平衡或 MPC 优化器。状态机只负责节拍与换相；站立 smoke 只能证明仿真基线稳定，不能证明机器人已经踏步。

## 运行

```bash
uv sync --dev
./run.sh
uv run pytest -q
```

`./run.sh` 默认用 16 个并行候选仿真站立 1 秒，并报告最低身体高度、水平漂移、双脚接触和运行耗时。可传入 `--num-sims 64 --seconds 2 --threads 8`。

依赖 `mjbatch` 通过 `../../AI/mjbatch` 的本地源码安装；若项目被移至其他机器，需相应调整 `pyproject.toml` 的路径来源，或改从包索引安装。

## 下一步

1. 在 MuJoCo 中分别求解两侧单腿静态支撑姿态，并验证最低 2 秒保持、躯干方向和双脚接触。
2. 用少量关节目标样条控制点参数化抬脚和落脚，在 `BatchRollout` 中批量评估候选；先尝试采样 MPC/CEM。落地时刻、支撑脚不打滑、身体 XY 漂移、偏航、关节速度及动作变化进入成本函数。
3. 先完成固定 1 Hz 的左右换脚闭环，再扩展到 0.5–2 Hz。低频通过延长单脚保持实现，不能仅等比例拉伸所有关节动作。
4. 在线控制以状态机执行离线优化的轨迹，用短视野 MPC 做平衡修正；在 Motrix 中复测以识别两种物理后端的接触差异。

本机初测：128 条候选、100 个控制节点（2 秒）、每节点 4 个 MuJoCo 子步，仅物理推进约需 101 毫秒，超过 20 毫秒控制周期；因此完整低频周期适合先离线优化。
